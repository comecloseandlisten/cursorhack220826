# Пользовательские сценарии

Источник правды для продукта, UI, бота, API и тестов. Не добавлять capture/filter-флоу вне этих шести.

Digest — лента собранных сообщений. Сообщение попадает в digest из веба, из чата через @бота или из лички с ботом. Коммент — то же сообщение с `parentMessageId` (см. [контракт](message-contract.md)). Реакция — отдельное действие. Фильтры работают по уже собранному.

---

## US-1. Прислать сообщение в приложении (веб) напрямую

**Зачем:** записать мысль, не уходя в мессенджер.

1. Пользователь открывает веб-интерфейс.
2. Пишет текст (опционально — картинка).
3. Отправляет.

**Тогда:** сообщение сразу в digest, автор = этот пользователь, канал = `web`, время = сейчас.

- [ ] Пустое сообщение не уходит.
- [ ] После отправки сообщение видно в ленте без перезагрузки страницы.
- [ ] Картинка, если есть, сохраняется и открывается из карточки.

---

## US-2. Прислать сообщение в чат и тегнуть бота, чтобы собрать digest

**Зачем:** сохранить данные из живого чата, не копируя руками.

1. Пользователь пишет в групповой чат и упоминает бота (`@bot …` или reply на бота).
2. Бот забирает это сообщение (текст, вложения, автор, время, ссылка на чат).

**Тогда:** сообщение в digest, канал = `chat`, видно кто тегнул и из какого чата.

- [ ] Без упоминания бота сообщение **не** попадает в digest.
- [ ] Текст рядом с тегом и вложения сохраняются.
- [ ] Повторный тег того же сообщения не плодит дубликат.

---

## US-3. Прислать сообщение боту

**Зачем:** быстро скинуть в digest из лички, без группы и без веба.

1. Пользователь пишет боту в личку (текст и/или картинка).
2. Бот подтверждает приём.

**Тогда:** сообщение в digest, канал = `dm`, автор = отправитель.

- [ ] Любое непустое входящее в личку попадает в digest.
- [ ] Команды бота (`/start` и т.п.) в digest не кладутся.


## US-6. Фильтрация по дате, тексту, объекту на картинке

**Зачем:** найти нужное в digest, а не скроллить всё.

Пользователь задаёт один или несколько фильтров. Лента показывает пересечение (AND).

| Фильтр | Поведение |
|--------|-----------|
| Дата | Диапазон `от` / `до` по времени сообщения. |
| Текст | Подстрока в теле сообщения и в комментариях, без учёта регистра. |
| Объект на картинке | Запрос вроде «кот», «чек», «паспорт». Попадают сообщения, на чьих картинках этот объект есть. |

- [ ] Пустые фильтры = вся лента.
- [ ] Дата отсекает сообщения вне диапазона.
- [ ] Текст ищет по сообщению и комментариям.
- [ ] Фильтр по объекту на картинке: нет картинки → нет попадания; есть объект → попадает.
- [ ] Сброс фильтров возвращает полный digest.
