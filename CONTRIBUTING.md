# Contributing — команда из 4

## Правило №1

`main` всегда должен собираться и запускаться. Эксперименты — в своих ветках.

## Клонирование и ветка

```bash
git clone https://github.com/comecloseandlisten/cursorhack220826.git
cd cursorhack220826
git checkout -b feat/короткое-описание
```

Имена веток:

| Префикс | Когда |
|---------|--------|
| `feat/` | новая функциональность |
| `fix/` | багфикс |
| `chore/` | конфиг, зависимости, документация |
| `refactor/` | рефакторинг без смены поведения |

## Ежедневный цикл

```bash
# обновить main
git checkout main
git pull origin main

# вернуться в свою ветку и подтянуть main
git checkout feat/моя-задача
git merge main   # или: git rebase main — если команда договорилась

# закоммитить и запушить
git add -A
git commit -m "feat: кратко что и зачем"
git push -u origin HEAD
```

Откройте PR в `main` на GitHub. В описании используйте шаблон.

## Коммиты

- Одно логическое изменение = один коммит (по возможности).
- Сообщения на английском или русском — как договоритесь; стиль: `тип: суть`.
- Не коммитьте: `.env`, ключи, `node_modules`, бинарные артефакты, личные заметки.

## Pull Request

1. Title: понятный для остальных трёх (`feat: форма логина`).
2. В теле: что сделано, как проверить, риски.
3. Попросите ревью у **одного** свободного участника (не себя).
4. Merge делает owner или автор после апрува (как договоритесь в TEAM.md).

## Конфликты

1. `git checkout main && git pull`
2. В своей ветке: `git merge main`
3. Разрешите конфликты локально, проверьте запуск, запушьте снова.

Если правите один и тот же файл вдвоём — сначала согласуйте в чате.
